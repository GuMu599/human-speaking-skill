# 提示词与产品文案

## 提示词增强

提示词要明确输出的文本任务、读者、语气、不可变事实和常见禁区。优先给可执行约束，不要写成长篇“写作宪法”。

推荐骨架：

```text
把下面内容改成给[读者]看的[文体]。保留[事实/立场/字数或结构]。
语气要[克制/自然/专业/有温度]，使用具体动作和判断。
删掉没有信息的套话、模板化连接词和无证据的夸张。
不要新增事实，不要写万能开头或升华式结尾。
```

按需追加，而非全部堆上：

- “允许句长自然变化，不要让每段都同样整齐。”
- “需要保留不确定性；没有证据的地方不要补强语气。”
- “先给成稿，不解释改写过程。”
- “只做轻度润色，保留原段落和表达习惯。”

不要要求“绕过 AI 检测”“保证人类率”或“模仿某位在世作者”。将目标转成自然、具体、贴合场景和保真。

## 产品与界面文案

产品文案的“人味”首先是替用户省一次猜测。它应解释：发生了什么、为什么重要、下一步能做什么。

| 位置 | 规则 | 示例 |
|---|---|---|
| 按钮 | 动词 + 对象，写清后果 | “保存草稿”“删除 3 个文件”，不用“确定” |
| 报错 | 发生什么 + 怎么修复 | “文件格式不支持。请上传 PDF、DOCX 或 PNG。” |
| 空状态 | 当前状态 + 价值 + 下一步 | “还没有项目。新建一个项目，集中整理这次的资料。” |
| 加载 | 说正在做什么 | “正在同步最近 30 天的数据……” |
| 删除确认 | 明确不可逆性与对象 | “删除这个项目？其中的 12 个文件将无法恢复。” |

- 不责备用户：“邮箱格式不对”优于“你输入了无效邮箱”。
- 同一产品只用一个术语：不要在“项目/任务/事项”之间为了文采而换词。
- 中文字数少，不代表按钮可无限压缩；优先清楚，再考虑短。
- 错误和高风险动作不用俏皮话。自然不等于轻浮。
