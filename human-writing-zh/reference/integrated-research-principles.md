# 综合研究原则

这份参考库把本项目对知乎、微信公众号、小红书、抖音和 GitHub 公开材料的精读，压缩成可执行的编辑判断。它吸收的是方法、检查顺序和提示词设计的抽象优点，不是第三方文章或仓库的逐句复制。

## 一、跨平台研究的结论

不同平台反复出现的有效共识是：先弄清文本要完成什么，再决定改动强度；先守住事实和任务，再处理“像不像人”。真正稳定的自然度来自材料、结构、具体动作、读者关系和场景语域的组合，而不是某个词、某种标点或一串“人味”口头禅。

可以复用的工作顺序：

1. 识别任务：诊断、轻改、人性化改写、深度重写、提示词增强或产品文案。
2. 识别场景：学术/技术、官方/职场、社媒/口播、私信、小说/叙事、UI/产品。
3. 建立信息账本：事实、数字、专名、引文、链接、责任归属、限定条件、否定关系、CTA、步骤和格式约束。
4. 判断材料是否够用。长篇非虚构材料不足时追问、检索或缩短，不用同义改写灌水。
5. 先删低增量内容，再修结构、段落职责和句子动作，最后才做词句润色。
6. 按读者和风险复核；高风险优先保真，低风险再追求读感和平台感。

## 二、信息账本与保真

编辑前把下列内容视为保护库存：数字、公式、术语、专有名词、引文键、原话、链接、时间线、因果关系、责任主体、否定关系、概率词和局限条件。改写前后逐项对照；没有来源的地方只能保留不确定性，不能用“更具体”之名补数字、案例、经历或结论。

把内容分成三类：

- **必须保留**：改变它就会改变事实或任务，例如金额、版本、接口、引用、报名步骤、联系方式和代码。
- **可重组**：段落顺序、句子长短、开头和收束，只要不改变论证与责任归属。
- **可删除**：无信息增量的套话、重复解释、空泛褒义和不服务任务的过渡。

## 三、材料门槛、结构和段落推进

长文不是短文的同义词扩写。若每段没有新事实、动作、例子、区别、后果或判断，就应合并、删掉或回到材料补证。一个实用的段落检查是：本段在回答什么问题？读者读完多知道了什么？下一段为什么必须接在这里？

优先处理结构级问题：标题是否承诺过大，开头是否直接进入问题，段落是否围绕一个职责推进，例子是否真的证明判断，结尾是否完成任务而不是万能升华。换词只解决表层问题，不能修复空心结构。

## 四、中文“AI 感”的动作级诊断

不要把词做成绝对禁词。单独出现的“首先”“重要”“赋能”未必有问题；更可靠的是看多个动作是否聚类：

- 翻案式“不是 A，而是 B”连续出现，先制造对立再给空泛升华；
- 整齐的三段式、四段式，段首预告、段尾总结，像套好的讲义；
- 抽象名词与抒情动词堆叠，读起来正确却没有对象和动作；
- 替读者预设“你可能也……”，用假共情代替真正回应；
- 过度礼貌、过度完整、每段都同样长，缺少重点和停顿；
- 结尾自动变成“总之/希望/让我们”，没有针对当前任务的下一步。

修复时优先合并重复动作、补回真实主语和动词、删掉没有后果的判断、改变段落职责；只有在结构已成立时才做词语替换。长短句变化服从内容，不为了“像人”故意打乱或制造语病。

## 五、场景路由

| 场景 | 优先级 | 主要动作 | 禁止的误伤 |
|---|---|---|---|
| 学术/技术 | 准确、可复核、责任清楚 | 保公式、数字、术语、引文、限定和局限；做改前后差异核对 | 默认口语化、删限定、把相关写成因果 |
| 官方/职场 | 清楚、稳妥、可执行 | 减少公文套话，保留礼貌、权限和责任边界 | 写成网感文案或替组织补承诺 |
| 社媒/口播 | 具体、顺口、有节奏 | 让开头尽早进入对象和冲突；保留 CTA、平台格式和必要标签 | 强行热词、故意错字、万能爆款承诺 |
| 私信/聊天 | 对人、对事、不过度解释 | 回应对方已说的内容，允许短句和停顿 | 替对方想、假共情、每句都总结 |
| 小说/叙事 | 视角、人物、动作、因果 | 区分叙述与对白；让人物通过行动和选择显性化 | 把虚构经历混进现实稿，或用作者旁白解释一切 |
| UI/产品 | 任务完成率、可理解、可操作 | 说明发生了什么、为什么、下一步怎么做；保留字段和错误条件 | 为自然感删按钮、步骤、参数和技术信息 |

## 六、自有样本与声音校准

只有用户明确提供且有权使用的自有样本，才可提取低层特征：常用句长、称呼、判断力度、口语/正式比例、习惯性收束。先描述样本观察，再让用户确认；不能把样本中的具体经历、观点、人设或他人表达直接移植到新稿，也不能从少量样本推断完整人格。

不提供在世作者、博主、账号或同事的可识别风格复刻。可以把用户说的“像某类文章”转译成抽象维度，例如“短句多、少比喻、先给结论、保留克制”，并注明这是功能描述而不是署名模仿。

## 七、提示词增强的通用骨架

高质量提示词不靠堆“禁止词”，而是交代：任务、读者、场景、保留项、允许改动、不可越界、输出格式和验收方式。推荐短骨架：

```text
任务：把下面文字改成【场景】下给【读者】看的版本。
保留：事实、数字、专名、引文、链接、原立场和不确定性。
允许：重排句子、删低增量套话、调整节奏和语气。
不要：补造经历/数据/引文，不改变结论，不删 CTA/步骤/代码，不模仿第三方可识别风格。
输出：直接给成稿；如有高风险事实，只列出需要核对的点。
```

对于“只诊断”，把输出改为“症状—影响—最小动作”，不代写全文；对于长篇，增加材料门槛和分段核对；对于学术/技术，增加差异核对清单；对于产品文案，增加用户下一步和失败路径。

## 八、评测与终检

评测应看可观察行为，不看“像不像人”的单一分数；不把检测分数当目标。至少检查：信息账本是否完整、段落是否推进、场景是否匹配、功能元素是否保留、归因与引用是否准确、是否出现伪具体性、是否把自然文本过度编辑。检测器最多提示某段值得回读，不足以鉴定作者、判断质量或作为发布门槛。学术与技术文本尤其应以差异核对和人工复核为准。

终检可采用低风险方法：朗读一遍、人工回读开头/转折/结尾、对照改前后差异、逐项核数字和链接。若文本本来已经自然、准确、适合场景，应停止修改；“必须再改一点”本身就是模板化冲动。

## 九、来源展示与引用规则

对外展示时只保留来源层级，不把研究日志当成引用清单：

- 社交平台只做平台级来源标注：知乎、微信公众号、小红书、抖音。不展示小红书、抖音、知乎或微信公众号的具体链接、标题、作者或账号。
- GitHub 上的 skill 可以保留一个参考链接，用来让使用者核对 skill 的公开定位；仅保留参考链接，只引用 skill，不引用普通项目、检测器、营销页或社交媒体文章。
- GitHub 上的非 skill 内容只标“GitHub 来源”，不展示具体仓库链接；它们吸收的只是抽象原则。
- 研究档案可以在仓库内部保存完整证据，但运行时不主动把内部研究链接塞进成稿或提示词。

## 十、不应吸收的做法

- 以“通过 AIGC 检测”“降低率”“隐藏 AI 痕迹”为目标的闭环、评分和阈值。
- 翻译循环、随机同义词、故意错别字、无意义口头禅、排版噪声和刻意跑题。
- 凭空加入第一人称经历、生活细节、情绪、记忆、MBTI、职业身份或“灵魂”。
- 把“禁用词表”、句长、被动比例、破折号/冒号数量当成绝对规则。
- 批量抓取第三方账号、蒸馏在世作者或博主的可识别文风，自动发布或冒充真人。
- 将候选摘要、营销标题、检测截图或未核验数字当作事实证据。

这些排除项不是保守，而是为了让“人话”来自真实材料和清楚判断，而不是来自伪装。
