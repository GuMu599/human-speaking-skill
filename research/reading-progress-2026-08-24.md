## 计数方法

1. 知乎和公众号只统计行内标记为“全文精读”的完整详情页；首表“已全文精读的平台材料”中的内容由该表标题直接标明状态。
2. GitHub 只统计实际阅读 README、`SKILL.md`、核心说明或许可证的项目。无许可证的项目可作风险/思路记录，但不复制其文本、规则或代码。
3. “达到 50”只说明精读量达到门槛，不意味着其中每项都适合进入 `human-writing-zh`。检测规避、伪造经历、第三方声口挪用和自动发布路线继续排除。

## 下一轮优先级

1. 继续补齐知乎公开正文，优先不同场景（学术、技术说明、小说、商业/社媒）与反例材料，直到 50。
2. 等公众号索引自然恢复后再读取剩余 17 篇；验证码必须由用户自行处理或自然失效。
3. 对小红书、抖音只做低频单页公开访问；只有取得完整正文或公开文稿才开始记入精读。
4. GitHub 不再以数量为主；后续仅补能填补现有评测空白的高质量一手项目，并在改变 skill 前先写“应改 / 不应改”测试。
